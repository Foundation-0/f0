00//How we work

The same rule for people and machines

Agents propose. Checkers verify. People decide.

Every result on these pages went through the same three steps, and each one tells you which step it has reached.

AI agents propose, freely. An agent is an AI model set loose on a task: it reads, writes code, runs it, looks at what happened and tries again. Agents are cheap and do not tire, so we let them try far more ideas than a person could, and most of those ideas fail. A proposal costs almost nothing, so on its own it proves nothing.

Checkers verify, strictly. A checker is a program that accepts a claim only if it passes a test with no room for opinion: arithmetic done exactly, with no rounding; every case of a finite search, run to the end; or a proof checker such as Lean, which accepts a proof only if every single step follows from the rules. A checker does not care who, or what, made the claim.

People decide, and sign. A person picks the question, reads what the checker actually confirmed, decides whether that is the thing we meant, and puts their name to it. When something turns out to be wrong, a person answers for it.

Every claim carries its status. Each result wears a plain label saying how far it has climbed, such as CLAIMED, PREPRINT, CONDITIONAL, PEER REVIEWED or LEAN-VERIFIED. A claim is never dressed up as a proof, and a check of one step is never sold as a check of the whole.

Exoplanets

Faint shadows in old starlight: 665 small-planet candidates in public NASA data, as of 14 Oct 2026.

Candidates · not confirmedNot peer reviewed

Founding member eumemic’s project, built with Claude Code. Aska sent ten merged pull requests, one of which built the first version of its website; one fix, restoring light curves the data reader had dropped (PR #6), led to a re-search that added 120 counted candidates.

SCHEMATIC · STACKING PASSES64 passes stacked

Why stacking works: noise shrinks like 1/√N as passes are added, until a dip too small to see once stands out. The dip is TIC 4206066’s published 398 ppm, 1.7 h signal; the noise is simulated.

mobius-x1

A claimed way to compute a basic transform on bits (the GF(2) Möbius transform) with fewer one-bit XOR steps than Yates’ 1937 recipe, for astronomically large inputs.

Not peer reviewed · AI-refereed only

Swapnil Jain’s repository. Aska wrote and ran the full-network check behind Theorem 2, its strongest version: 3,456,000 bank swaps tested in a network of size h = 10, with zero failures (merged PR #1).

The matrix the transform computes, made here from Pascal’s triangle with the odd entries filled. The claimed saving only appears when the input has billions of digits.

Lean-verifiedTested on every inputNot peer reviewed
